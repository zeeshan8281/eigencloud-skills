Build Log
v1 Agent Skills the markdown-only beginning
  • Shipped as pure Agent Skills — plain SKILL.md files an agent reads directly. No SDK, no dependencies, no server.
  • Auto-discovered by Claude Code straight from the npm package via a postinstall that drops the skill into .claude/skills/.
  • Covered the EigenLayer ecosystem through the EigenExplorer API: operators, AVS, stakers, restaking positions, rewards & APY, delegation & registration events.
  • Each skill = a markdown spec + ready-to-run curl examples the agent executes itself — zero glue code, works in any agent that can read files.
  • Limitation: read-only data lookups. The agent could answer questions, but couldn't do anything.
v2 EigenCompute focus + MCP server from reading to doing
  • Pivoted the entire package to EigenCompute TEE deployment — retired the EigenExplorer/DA data skills to go deep on one thing: shipping apps into enclaves.
  • Added a first-class MCP server (eigen-mcp) over stdio — installs as a real tool provider in Cursor, Claude Desktop, Cline, Codex CLI and any MCP client.
  • 10 lifecycle tools: deploy, list, info, logs, start, stop, terminate, upgrade, env_set, whoami.
  • Wraps @layr-labs/ecloud-cli non-interactively — collapses 6+ interactive prompts into one agent-driven call, so a full build → deploy runs hands-free.
  • Sealed secrets — env vars encrypted client-side, decrypted only inside the TEE via KMS attestation.
  • Marketing site + one-paste MCP config; published to npm as eigen-skills.
  • Limitation: you could deploy, but couldn't prove what was running — and it only worked from a local subprocess.
v3.0 Verifiable Deployments + Remote access trust, and reach
  • eigencompute_verify — reads the block-anchored on-chain release record (app releases) and reconciles the deployed image digest against build provenance and your expected digest. Returns a real pass/fail, and flags hand-built "dev" images as NOT VERIFIABLE.
  • eigencompute_init_verifiable — scaffolds a GitHub Actions pipeline that builds linux/amd64, pushes to your registry, and signs build provenance (source commit → image digest). Turns an unprovable dev image into one verify can confirm.
  • Together they close the loop: scaffold → deploy → verify, proving the chain source commit → signed build → on-chain record → attested TEE.
  • Remote MCP over HTTP — new eigen-mcp-http server with Streamable HTTP + legacy SSE transports, so remote and web-based IDE clients connect by URL, not a local process.
  • Bearer-token auth on the HTTP transport (CORS + public /health probe) for safe public hosting.
  • 12 tools total, and a leaner package — dropped the dead chat-server, duplicate landing page, and 3 unused dependencies.
  • Next: deploy guardrails + continuous attestation monitoring with digest-drift alerts.
  • Next: hosted multi-tenant server with OAuth 2.1 — zero local setup from any IDE.
